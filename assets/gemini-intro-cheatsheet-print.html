Extract Sections from Text
class Section(BaseModel):
    title: str
    content: str

def extract_sections(text: str):
    response = client.models.generate_content(
        model="gemini-3.8-flash",
        contents=(
            "Extract main sections "
            f"from:\n\n{text}"
        ),
        config={
            "response_mime_type":
                "application/json",
            "response_schema": list[Section],
        },
    )
    return response.parsed

5. Embeddings & Semantic Search
Generate Embeddings
# Single embedding
result = client.models.embed_content(
    model="gemini-embedding-2",
    contents="What is the meaning of life?"
)
vector = result.embeddings[0].values

# With a task instruction (recommended)
result = client.models.embed_content(
    model="gemini-embedding-2",
    contents="Task: retrieve documents that "
             "answer this question. "
             "search query text"
)
Task Instructions

⚠ task_type does not apply to gemini-embedding-2 — it is silently ignored. Prepend the task to the text instead:

  • "Task: index this document for retrieval." — building a store
  • "Task: retrieve documents that answer this question." — search query
  • "Task: find semantically similar text." — comparing pairs
  • "Task: classify this text." — classification
  • "Task: group similar documents." — clustering
6. Simple RAG with Embeddings
Build Document Store & Semantic Search (dot product)
import numpy as np, pandas as pd

# 1. Build store — embed each document once
df = pd.DataFrame({"Title": titles, "Text": texts})
df["Embeddings"] = df.apply(
    lambda row: client.models.embed_content(
        model="gemini-embedding-2",
        contents=f"Task: index this document for retrieval. "
                 f"Title: {row['Title']}. Content:\n{row['Text']}"
    ).embeddings[0].values,
    axis=1,
)

# 2. Search — cosine via dot product (embeddings are unit-normalised)
def find_best_passage(query: str, dataframe: pd.DataFrame) -> str:
    q_emb = client.models.embed_content(
        model="gemini-embedding-2",
        contents=f"Task: retrieve documents that answer "
                 f"this question. {query}"
    ).embeddings[0].values
    scores = np.dot(np.stack(dataframe["Embeddings"]), q_emb)
    return dataframe.iloc[np.argmax(scores)]["Text"]

# 3. Answer with context
passage = find_best_passage("best prompting techniques?", df)
answer = client.models.generate_content(
    model="gemini-3.8-flash",
    contents=f"Answer using this context:\n{passage}\n\nQuestion: best prompting techniques?"
)
print(answer.text)

9. Prompt Engineering Techniques
Core Techniques
  • Zero-Shot — Direct task, no examples. Start here.
  • Few-Shot — 3–5 input/output examples. Best for format control.
  • Role Prompting — "Act as a senior Python developer..." Shapes tone & expertise.
  • System Prompt — Sets global rules: "Only return JSON", "Be concise".
  • Contextual Prompt — Inject relevant background before the question.
Advanced Techniques
  • Chain of Thought (CoT) — Append "Let's think step by step." Pair with a high thinking level (see §10).
  • Self-Consistency — Run CoT N times, take the majority answer.
  • Step-Back Prompting — Ask the general question first, use answer as context.
  • ReAct — Reason + Act: interleave Thought / Action / Observation loops for agents.
  • APE — Use LLM to generate & evaluate prompt variants automatically.
10. Model Configuration Parameters
Output Controls
Parameter Range Low Value High Value Recommended Starting Point
thinking_level
(nested — see below)		 low | medium | high Faster, cheaper, less reasoning Deeper reasoning, more billed tokens medium (the default) — drop to low for cost
Max Output Tokens 1 – model max Controls cost & latency. Too short truncates JSON — add buffer. Set explicitly for production
⚠ thinking_level is not a top-level kwarg. It lives on the nested ThinkingConfig object — passing it directly to GenerateContentConfig raises a pydantic ValidationError:
config=types.GenerateContentConfig(thinking_config=types.ThinkingConfig(thinking_level="low"))
⚠ Deprecated sampling parameters (July 2026)
  • temperature, top_p, top_k are deprecated — strip them from generation configs. Also remove candidate_count (unsupported on Gemini 3+).
  • Use thinking_level instead — low | medium (default) | high — passed nested, not as a top-level kwarg:
    config=types.GenerateContentConfig(thinking_config=types.ThinkingConfig(thinking_level="low"))
  • On gemini-3.8-flash, minimal is not supported and thinking cannot be disabled — there is no thinking_budget=0 off-switch.
  • Setting both thinking_level and the legacy thinking_budget in one request returns a 400 error.
11. Prompt Writing Best Practices
Do This
  • Start with strong action verbs: Summarize, Classify, Extract, Translate
  • Be specific about format: "Return a JSON array with fields: name, score"
  • Use positive instructions — tell the model what TO do
  • Add examples (few-shot) when format matters
  • Set temp=0 for deterministic/reasoning tasks (math, CoT)
  • Use variables: {city}, {user_input} for reusability
  • Document your prompts: version, model, settings, output
Avoid This
  • Vague instructions: "Write something about AI" → too broad
  • Negative-only constraints: "Don't mention X" → weaker than "Focus only on Y"
  • Assuming CoT output → always set temp=0 for reasoning
  • Ignoring token limits → JSON gets truncated; use json-repair as safety net
  • Using prompts without testing on edge cases
  • Skipping the iterative loop: Craft → Test → Analyze → Document → Refine
