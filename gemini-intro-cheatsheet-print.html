Extract Sections from Text
class Section(BaseModel):
    title: str
    content: str

def extract_sections(text: str):
    response = client.models.generate_content(
        model="gemini-3.5-flash",
        contents=(
            "Extract main sections "
            f"from:\n\n{text}"
        ),
        config={
            "response_mime_type":
                "application/json",
            "response_schema": list[Section],
        },
    )
    return response.parsed

5. Embeddings & Semantic Search
Generate Embeddings
# Single embedding
result = client.models.embed_content(
    model="gemini-embedding-2",
    contents="What is the meaning of life?"
)
vector = result.embeddings[0].values

# With task type (recommended)
result = client.models.embed_content(
    model="gemini-embedding-2",
    contents="search query text",
    config=types.EmbedContentConfig(
        task_type="RETRIEVAL_QUERY"
    )
)
Embedding Task Types
  • RETRIEVAL_DOCUMENT — indexing docs into a store
  • RETRIEVAL_QUERY — encoding a search query
  • SEMANTIC_SIMILARITY — comparing text pairs
  • CLASSIFICATION — text classification tasks
  • CLUSTERING — grouping similar documents
6. Simple RAG with Embeddings
Build Document Store & Semantic Search
import numpy as np, pandas as pd

# 1. Build store — embed each document once
df = pd.DataFrame({"Title": titles, "Text": texts})
df["Embeddings"] = df.apply(
    lambda row: client.models.embed_content(
        model="gemini-embedding-2",
        contents=f"Title: {row['Title']}. Content:\n{row['Text']}",
        config=types.EmbedContentConfig(task_type="RETRIEVAL_DOCUMENT")
    ).embeddings[0].values,
    axis=1,
)

# 2. Search — dot product (embeddings are unit-normalised)
def find_best_passage(query: str, dataframe: pd.DataFrame) -> str:
    q_emb = client.models.embed_content(
        model="gemini-embedding-2",
        contents=query,
        config=types.EmbedContentConfig(task_type="RETRIEVAL_QUERY")
    ).embeddings[0].values
    scores = np.dot(np.stack(dataframe["Embeddings"]), q_emb)
    return dataframe.iloc[np.argmax(scores)]["Text"]

# 3. Answer with context
passage = find_best_passage("best prompting techniques?", df)
answer = client.models.generate_content(
    model="gemini-3.5-flash",
    contents=f"Answer using this context:\n{passage}\n\nQuestion: best prompting techniques?"
)
print(answer.text)

9. Prompt Engineering Techniques
Core Techniques
  • Zero-Shot — Direct task, no examples. Start here.
  • Few-Shot — 3–5 input/output examples. Best for format control.
  • Role Prompting — "Act as a senior Python developer..." Shapes tone & expertise.
  • System Prompt — Sets global rules: "Only return JSON", "Be concise".
  • Contextual Prompt — Inject relevant background before the question.
Advanced Techniques
  • Chain of Thought (CoT) — "Let's think step by step." Use temp=0.
  • Self-Consistency — Run CoT N times at higher temp, take majority answer.
  • Step-Back Prompting — Ask general question first, use answer as context.
  • ReAct — Reason + Act: Thought / Action / Observation loops for agents.
  • APE — Use LLM to generate & evaluate prompt variants automatically.
10. Model Configuration Parameters
Sampling Controls
Parameter Range Low Value High Value Recommended Start
Temperature 0 – 1.0 Deterministic, factual Creative, diverse 0.2 (factual) | 0.9 (creative) | 0 (CoT)
Top-K 1 – 40+ Conservative (20) More diverse (40+) 30 balanced default
Top-P 0 – 1.0 Tighter logic (0.9) More variety (0.99) 0.95 balanced default
Max Output Tokens 1 – max Controls cost & latency. Too short truncates JSON — add buffer. Set explicitly in production
11. Prompt Writing Best Practices
Do This
  • Start with action verbs: Summarize, Classify, Extract, Translate
  • Be specific about format: "Return a JSON array with fields: name, score"
  • Use positive instructions — tell the model what TO do
  • Add examples (few-shot) when format matters
  • Set temp=0 for deterministic/reasoning tasks (CoT)
  • Use variables: {city}, {user_input} for reusability
  • Document your prompts: version, model, settings, output
Avoid This
  • Vague instructions: "Write something about AI" → too broad
  • Negative-only constraints: "Don't mention X" → weaker than "Focus only on Y"
  • Assuming CoT output at high temp → use temp=0 for reasoning
  • Ignoring token limits → JSON gets truncated; use json-repair as safety net
  • Testing only happy path — always test edge cases
  • Skipping: Craft → Test → Analyze → Document → Refine loop
